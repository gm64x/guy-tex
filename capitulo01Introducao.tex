\chapter{Introdução}
\label{cap:01}

Nas últimas décadas, a Engenharia de Software consolidou-se como uma disciplina essencial para o processo de desenvolvimento de software. Segundo \citeonline{Pressman2016} e \citeonline{Sommerville2019}, os sistemas computacionais passaram a exercer papel central em atividades sociais, econômicas e organizacionais.

Entretanto, à medida que as funcionalidades dos sistemas aumentam, cresce também a complexidade do código-fonte. \citeonline{Sommerville2019} aponta que a complexidade é um dos maiores inimigos da confiabilidade, tornando insuficiente garantir a qualidade apenas por inspeção manual. Esse cenário impõe um desafio crítico: verificar se a lógica do software se comporta conforme o esperado. Como afirma \citeonline{Myers2014}, o objetivo do teste não é provar que o software funciona, mas encontrar falhas antes que elas cheguem ao usuário.

É neste contexto que se destacam as técnicas de teste de caixa branca (estrutural), que analisam a lógica interna do componente para identificar caminhos de execução, estruturas de decisão e fluxos que devem ser considerados durante o planejamento dos testes. Essa análise pode ser representada pelo Grafo de Fluxo de Controle (GFC), uma estrutura abstrata em que nós representam blocos de instruções e arestas descrevem o fluxo de controle e os desvios lógicos do programa \cite{Delamaro2013}.

O emprego do GFC fundamenta a aplicação de métricas estruturais, com destaque para a Complexidade Ciclomática. Introduzida por \citeonline{McCabe1976}, esta métrica permite mensurar a complexidade lógica de um módulo e estimar o número de caminhos linearmente independentes que podem orientar a definição de casos de teste.



\section{Justificativa}

A garantia da qualidade de software consolidou-se como um fator crítico de sucesso na indústria de tecnologia. A presença de defeitos em ambientes de produção não afeta apenas a experiência do usuário, mas gera prejuízos financeiros significativos e, no caso de sistemas críticos, pode comprometer a segurança operacional \citeonline{Boehm2001}.

\pagebreak

Sob essa ótica, estudos sobre redução de defeitos alertam que o custo para corrigir uma falha após a entrega do software tende a ser maior do que durante a fase de desenvolvimento. Entretanto, a crescente complexidade dos sistemas modernos dificulta a detecção manual de erros lógicos.

Este trabalho propõe a aplicação de técnicas consolidadas da Engenharia de Software, apresentando uma ferramenta que busca auxiliar analistas, engenheiros e programadores no processo de verificação e validação estrutural de código-fonte.


\section{Objetivos}

\subsection{Objetivo Geral}
O objetivo desta pesquisa é desenvolver o Guy, uma extensão para o \textit{Visual Studio Code} destinada à análise estrutural de código-fonte e à geração automática do Grafo de Fluxo de Controle (GFC), fornecendo uma base visual e analítica para auxiliar desenvolvedores na mensuração da complexidade lógica e no planejamento de testes estruturais.

\subsection{Objetivos Específicos}
Para alcançar o objetivo geral, foram definidos os seguintes objetivos específicos:

\begin{itemize}
	\item Fundamentar conceitos de Teste de Software, Caixa Branca e a métrica de Complexidade Ciclomática de McCabe;
	\item Implementar um analisador capaz de identificar estruturas de decisão e repetição no arquivo de código-fonte aberto no editor;
	\item Desenvolver o algoritmo para mapeamento e renderização visual dos nós e arestas do Grafo de Fluxo de Controle;
	\item Automatizar o cálculo da complexidade ciclomática ($V(G)$) com base na topologia do grafo gerado;
	\item Desenvolver uma extensão para o editor \textit{Visual Studio Code} para que o usuário tenha acesso à ferramenta localmente;
    \item Validar a ferramenta desenvolvida por meio da comparação entre os grafos e valores de complexidade gerados e os resultados esperados para os códigos analisados;
\end{itemize}
